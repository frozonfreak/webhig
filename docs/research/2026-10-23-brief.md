## Review rationale and compatibility

- **User harm:** Failed chunks can strand a route and discard drafts. Stale accessibility trees hide current choices; activation defects block tasks. Invalid or repaired tool calls can execute an unintended action.
- **Capability condition:** Module guidance applies where routes/features load code asynchronously. AT checks apply to dynamic options, native required radio groups and activation. Schema guidance applies to agent execution systems, not arbitrary websites.
- **Evidence:** Primary sources are linked above. Browser/AT execution is pending; no measured accessibility pass is claimed.
- **Alternatives:** Same-URL retry, refreshed/versioned module URLs or reload with draft restoration can meet recovery outcomes. Rejecting invalid tool calls is sufficient; repair is optional.
- **Test cases:** Fail initial and repeated module requests, recover by keyboard and compare drafts. Inspect/announce inserted and removed options, validate either radio choice and count AT activations. Change tool candidates/schemas and verify invalid calls and unauthorized substitutions have no effects.
- **Exceptions:** No Chrome-only retry dependency, no author failure solely for a browser/AT defect, no experimental CSS mandate or automated agent-readiness score. Logs stay redacted under §9.4.
- **Compatibility:** Minor guidance expansion and clarification of existing recovery outcomes. No new IDs, severity changes, Layer 0 changes or tightened mandatory threshold. Agent review is informative, not a blocking conformance gate. Rule wording remains subject to repository governance review before merge.

The separate audit site is not implemented or deployed by this repository change. These fixtures and procedures are ready for its test review; actual browser/AT results must be recorded separately.
