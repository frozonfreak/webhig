The Web HIG

A practical standard for how web interfaces should behave.

The Web HIG gives teams a shared set of rules for usable, accessible, responsive, performant, predictable, and safe web applications.

Design systems define what your UI looks like.

The Web HIG defines how it behaves.

It is not a component library, CSS framework, or visual theme. Keep your existing stack and use HIG as a practical behavior and quality contract. Why it exists →

New to The Web HIG?

Start here if you are seeing the project for the first time. The short version: HIG helps you decide what should happen around your components when real users load, navigate, submit, search, fail, recover, resize, or delete something.

What it is

A vendor-neutral, versioned web interface standard for behavior, interface states, accessibility, performance, security UX, and AI-assisted implementation.

What it is not

Not a component library, Figma kit, CSS framework, brand system, or replacement for WCAG, HTML, CSS, ARIA, or your design system.

When to use it

Use it while building, reviewing, auditing, or asking an AI coding agent to change a web interface consistently.

Companion: Design Decision Method

You can use WebHIG with your existing design process. WebHIG and Design Decision Method (DDM) help with different parts of the work, and each stands on its own.

What WebHIG and Design Decision Method each help you do
Name What it helps you do Example
WebHIG Build interfaces that behave clearly, consistently and accessibly Make errors understandable and preserve entered information when saving fails
Design Decision Method (DDM) Choose an interface that fits the people and task Decide whether a task needs one form or a step-by-step flow

If you also want help choosing layouts, navigation and interaction patterns, DDM gives you a structured way to make those decisions. DDM is optional.
